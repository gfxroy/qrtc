PROJECT: qrtc (repo name qrtc). One-liner: "Send a file between two devices directly. No server, no account — the handshake is a QR code."
Core flow (zero signaling server): Sender picks file(s) -> creates RTCPeerConnection with public STUN (stun:stun.l.google.com:19302), DataChannel, waits for ICE gathering complete (non-trickle, timeout 3s), compresses the offer and shows it as a QR code + a copyable link (https://gfxroy.github.io/qrtc/#o=<blob>) . Receiver opens the link or scans the QR with the in-app camera scanner (use jsQR or BarcodeDetector fallback) -> generates answer -> shows answer QR + copy code -> sender scans/pastes it -> connected -> transfer.
Hard parts in src/lib:
1. SDP minifier: extract only what is needed (ice-ufrag, ice-pwd, DTLS fingerprint, setup role, candidates host/srflx with ip/port/type, sctp-port) into a compact binary encoding (fingerprint as 32 raw bytes, IPv4 as 4 bytes, ports as uint16), then deflate (CompressionStream 'deflate-raw' or fflate) and base64url. And the inverse: rebuild a valid full SDP that Chrome/Firefox/Safari accept. Target <300 chars so the QR is easy to scan. Unit-test round trips with real SDP samples from Chrome and Firefox (include fixtures).
2. Transfer protocol over the DataChannel: header message (name, size, mime, chunk size), 64KB chunks, backpressure using bufferedAmountLowThreshold, progress + speed + ETA, multiple files queued, streaming SHA-256 (implement incremental SHA-256 in TS or use a small lib; WebCrypto cannot stream) verified at the end, receiver saves via Blob download (and File System Access API streaming when available).
3. Connection state machine (idle, offering, awaiting-answer, connecting, connected, transferring, done, failed) with clear failure messages, e.g. explain when both sides are behind symmetric NAT and direct connection is impossible without TURN (be honest in UI + README).
4. Short safety code: both screens show a 4-word code derived from hashing both DTLS fingerprints so users can confirm no MITM.
UI: home with two big options "Send" and "Receive". Minimal steps, big QR (white on #0a0a0a card padded), camera scanner fullscreen on mobile, progress as a thin white bar with numbers. Also works on the same Wi-Fi with no internet beyond loading the page.
Tests: SDP encode/decode round trips, protocol framing, chunker, SHA-256 against known vectors, state machine transitions. Also write a node or playwright-free integration test if feasible; otherwise document a manual test.
